# 翻译流程

当前引擎为 PDFMathTranslate-next 2.9.0 / BabelDOC 0.6.2，输入英文文本 PDF，输出保持原分页和页面尺寸的简体中文 PDF。

## 职责

| 层 | 职责 |
| --- | --- |
| `src/translation/api.ts` | Base URL 校验、连接测试、可选模型目录、错误脱敏 |
| `src/translation/config.ts` | 模型服务设置及参数范围归一化 |
| `src/translation/backend.ts` | 准备运行环境、启动独立 Python 进程、接收进度、取消任务 |
| `runtime/pdfmath/bridge.py` | 构建上游配置、运行引擎、拦截段落错误、验证和发布产物 |
| `src/translation/manager.ts` | 文档互斥、任务关联、产物接收、保存及移动恢复 |
| `src/translation/protocol.ts` | 清单、路径、PDF 页数、尺寸及 SHA-256 校验 |

## 模型接口

配置一个 OpenAI 兼容服务。连接测试和段落翻译使用 Chat Completions；模型目录可选调用 `GET /models`。Base URL 保留自定义路径前缀，也接受完整 completions 地址。

API Key 存在 Obsidian SecretStorage 中，`data.json` 只记录密钥引用。运行进程通过 stdin 接收 Key 和配置；进程参数及任务文件不含 Key。模型只接收翻译所需文本，不要求视觉输入、工具调用或结构化输出。

默认超时 60 秒、并发及每秒请求上限 4、不发送推理强度、关闭自动术语提取。超时是单次请求限制，可在设置中调整为 10–600 秒。

## 执行与交付

1. 校验 API 配置，验证模型连接。
2. 在工作目录内复用或安装 uv、隔离的 Python 3.12.12 环境及固定版本依赖。识别模型和字体由上游下载。
3. 保存源文快照与 `job.json`，通过 PDFMathTranslate 的 SettingsModel / create_babeldoc_config 构建 BabelDOC 配置。
4. 在同一 Python 进程调用 BabelDOC `async_translate`，上报解析、识别、翻译和排版事件。收到 finish 事件即结束迭代，防止已完成任务继续等待开放进度流。
5. 检测到段落失败或内容过滤日志时判定失败，即使上游已经生成 PDF，也不发布完成清单。
6. 全文完成后验证源快照、输出路径、页数及每页尺寸，拆出单页 PDF，写入 `final.pdf`，原子发布 `manifest.json`。
7. TypeScript 接收端再次校验摘要和页面结构，再检查当前原文是否仍与源快照一致。通过后显示译文，使用排他创建保存原文件旁的 `.zh-CN.pdf`，并记录 `saved.json`。

翻译期间显示阶段进度，页面产物在全文完成后发布。取消会终止独立进程组，并在进程退出前持有文档锁；失败和取消后的重试重新处理全文。

## 任务与恢复

任务位于 `工作目录/documents/<指纹>/translation/`，运行环境位于 `工作目录/tools/pdfmath-2.9.0-v1/`。指纹包含文档标识、源内容 SHA-256、引擎版本、服务地址、模型、推理强度及术语设置。禁用上游共享段落缓存，避免不同服务产生错误的缓存关联。

原文或父文件夹在 Vault 内移动后，当前路径未找到任务时按源内容和同配置指纹查找已完成任务。任务保留创建时的标识，支持后续再次移动。已保存译文按原路径、当前原文目录中的导出文件名及当前原文对应的 `.zh-CN.pdf` 查找，并验证其保存摘要；缺失时可从有效完成产物重新导出。打开视图监听 Vault rename 事件，自动恢复关联。

内容、模型配置不匹配，以及未完成或无效任务均不会用于移动恢复。恢复完成任务不调用翻译 API。

## PDF 识别边界

上游使用版面识别与原生文本信息合并段落、处理公式及排版。扫描 PDF 暂不作为支持范围。

上游扫描检测可能将稀疏原生文字误判为扫描件：移除少量文字前后整页图像过于相似。适配层仅对每页无图片（含内联图片）、且至少有 20 个可见原生字母或数字的文档跳过该相似度检测。隐藏 OCR 文字、含图片的页面等继续使用上游检测。

复杂公式、算法小字号、参考文献及密集版式仍存在上游质量限制。插件的结构和错误检查不能替代译文语义及版面的人工审校。
